在 SQLite 中，增加列使用 **`ALTER TABLE ADD COLUMN`** 语句。语法很简单，但有几个**极容易踩坑的硬性限制**，我直接给你最清晰的写法和避坑指南。

---

### 1. 核心语法（最常用写法）

```sql
ALTER TABLE 表名 ADD COLUMN 列名 数据类型 约束;
```

**实际例子**：给 `users` 表增加一个 `city`（城市）列，类型为文本。
```sql
ALTER TABLE users ADD COLUMN city TEXT;
```
执行后用 `.schema users` 查看，就能看到新列已经加上去了。

---

### 2. ⚠️ 必须知道的“致命限制”（非常重要）

如果你加列时带了 `NOT NULL`（非空约束），**必须同时指定默认值 `DEFAULT`**，否则 SQLite 会直接报错！

**❌ 错误写法（会报错）**：
```sql
-- 如果表里已有数据，这行会报错：Cannot add a NOT NULL column with default value NULL
ALTER TABLE users ADD COLUMN age INTEGER NOT NULL;
```

**✅ 正确写法（带上默认值）**：
```sql
-- 新增列不允许为空，且默认设为 0
ALTER TABLE users ADD COLUMN age INTEGER NOT NULL DEFAULT 0;
```

---

### 3. 其他常用约束组合

| 你想实现的效果 | 正确 SQL 命令 |
| :--- | :--- |
| 增加一个可为空的文本列 | `ALTER TABLE users ADD COLUMN email TEXT;` |
| 增加一个带默认值的数字列 | `ALTER TABLE users ADD COLUMN score INTEGER DEFAULT 0;` |
| 增加一个唯一约束的列（可为空） | `ALTER TABLE users ADD COLUMN phone TEXT UNIQUE;` |
| 增加一个自增主键列（**仅当表为空**时才建议操作） | `ALTER TABLE users ADD COLUMN new_id INTEGER PRIMARY KEY;`（注意：已有主键时不能加） |

---

### 4. 如何一次性增加多列？

**SQLite 不支持**一条 `ALTER TABLE` 语句加多列，你必须分多条写：

```sql
ALTER TABLE users ADD COLUMN city TEXT;
ALTER TABLE users ADD COLUMN province TEXT;
ALTER TABLE users ADD COLUMN country TEXT DEFAULT '中国';
```

---

### 5. 验证列是否添加成功

添加后，用以下命令查看最新的表结构：

```sql
.schema users
```
或者查看列的详细信息（SQLite 特有）：
```sql
PRAGMA table_info(users);
```

---

### 6. 🚫 SQLite 加列的两大“绝对禁区”

| 禁区 | 原因 |
| :--- | :--- |
| **不能指定列的位置**（比如插入到第一列） | SQLite 只把新列加在**最后面**，不支持 `AFTER` 或 `FIRST` 子句（那是 MySQL 的功能）。 |
| **不能添加 `PRIMARY KEY` 到已有数据的表** | 除非表是空的，否则 SQLite 不允许通过 `ALTER` 添加主键。如果必须加，只能重建表（先建新表，迁移数据，删旧表）。 |

---

### 7. 终极补救：如果加错了列怎么办？

SQLite **不支持直接删除列**（直到 3.37.0 版本后才开始支持 `DROP COLUMN`，但默认很多环境未开启）。
如果你加错了，最稳妥的“后悔药”是：
1. 创建一张不含该列的新表（临时表）。
2. 将旧表数据复制过去。
3. 删除旧表，重命名新表。

**总结**：日常最安全的加列口诀就是 —— **`ALTER TABLE 表名 ADD COLUMN 列名 类型;`**，只要不带 `NOT NULL` 就绝对不会出错。😊

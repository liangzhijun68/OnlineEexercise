很遗憾，SQLite 原生并不支持在指定位置插入列。

在 SQLite 中，`ALTER TABLE ADD COLUMN` 语法有一个硬性限制：**新列总是被添加到表的末尾**。这是 SQLite 引擎的底层行为，无法通过简单的 SQL 命令改变。

不过，如果列的顺序对你非常重要（例如为了便于查看或对接旧代码），可以参考下面两种方案：

### 方案一：创建视图（推荐，最安全）

**原理**：不改变原表结构，创建一个**视图**来“重塑”你想要的列顺序。

**优点**：无需改动原表和已有数据，可以随时删除重建，非常灵活安全。

**操作**：
```sql
-- 假设原表 users 有 id, name, age 三列，你想让 age 显示在 name 前面
CREATE VIEW users_view AS
SELECT id, age, name FROM users;

-- 之后查询时，直接查这个视图即可
SELECT * FROM users_view;
```
之后查询时直接使用视图名即可，它会返回你指定的列顺序。

### 方案二：重建表（最彻底）

**原理**：通过“移花接木”的方式彻底改变物理表结构。

**优点**：彻底改变物理表结构，`SELECT *` 的结果也会按新顺序排列。

**缺点**：操作复杂，涉及数据迁移，**务必提前备份**。

**操作步骤**：
1.  **重命名旧表**：`ALTER TABLE users RENAME TO users_old;`
2.  **创建新表**：按照你想要的列顺序创建新表 `users`。
3.  **迁移数据**：`INSERT INTO users (列1, 列2, ...) SELECT 列1, 列2, ... FROM users_old;`
4.  **清理旧表**：确认数据无误后，`DROP TABLE users_old;`

### 💎 总结与建议

*   **如果只是为了查看方便**：**方案一（创建视图）** 是首选，安全且零风险。
*   **如果必须修改物理表结构**：只能采用**方案二（重建表）**，但操作前请务必备份数据。

**关于可视化工具**：像 Navicat 或 SQLite Expert 等 GUI 工具，虽然界面上的“拖拽调整”看起来很直观，但其背后执行的也是“重建表”的逻辑。

### 重建表代码示例
下面给你一个**完整的、可直接套用的SQLite重建表代码模板**。

为了演示效果，我们模拟一个**真实场景**：`users` 表原有 `id, name, age` 三列，现在你想**把新加的 `city` 列插在 `name` 和 `age` 之间**（因为SQLite默认只能加在末尾，所以必须重建）。

---

#### 完整代码模板（直接复制修改）

```sql
-- 1. 关闭外键约束（防止迁移时报外键错误）
PRAGMA foreign_keys = OFF;

-- 2. 开启事务（如果中间出错，可以整体回滚）
BEGIN TRANSACTION;

-- 3. 将旧表重命名为备份表
ALTER TABLE users RENAME TO users_old;

-- 4. 按你想要的列顺序创建全新的表
--    （这里我把 city 放在了 name 和 age 中间）
CREATE TABLE users (
    id   INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT    NOT NULL,
    city TEXT    DEFAULT '未知',  -- 新列插在这里
    age  INTEGER
);

-- 5. 将备份表中的数据迁移到新表
--    注意：列名要一一对应，如果旧表没有 city，则填默认值
INSERT INTO users (id, name, city, age)
SELECT 
    id, 
    name, 
    COALESCE(city, '未知'), -- 如果旧表已有city则保留，没有则用默认值
    age
FROM users_old;

-- 6. 删除备份表（确认数据无误后执行）
DROP TABLE users_old;

-- 7. 提交事务
COMMIT;

-- 8. 重新开启外键约束
PRAGMA foreign_keys = ON;
```

#### 针对你情况的三种改造示例

##### 场景A：只调整列顺序，不增删列
想把 `age` 挪到 `name` 前面（顺序变为 `id, age, name`）：
```sql
-- 第4步改为：
CREATE TABLE users (
    id   INTEGER PRIMARY KEY,
    age  INTEGER,
    name TEXT
);
-- 第5步改为：
INSERT INTO users (id, age, name)
SELECT id, age, name FROM users_old;
```

##### 场景B：加列并放在指定位置（比如将 `email` 插在第一列后面）
```sql
-- 第4步改为：
CREATE TABLE users (
    id    INTEGER PRIMARY KEY,
    email TEXT,               -- 新列放在第二列
    name  TEXT,
    age   INTEGER
);
-- 第5步改为：
INSERT INTO users (id, email, name, age)
SELECT id, NULL, name, age FROM users_old;  -- 新列暂时填NULL
```

##### 场景C：同时删除某一列（比如不要 `age` 列）
```sql
-- 第4步改为（直接不写 age）：
CREATE TABLE users (
    id   INTEGER PRIMARY KEY,
    name TEXT
);
-- 第5步改为（只选存在的列）：
INSERT INTO users (id, name)
SELECT id, name FROM users_old;
```

#### ⚠️ 极易出错的三个坑（必看）

| 坑点 | 后果 | 解决方案 |
| :--- | :--- | :--- |
| **忘记处理 `AUTOINCREMENT`** | 迁移后自增序号可能重置，导致主键冲突 | 如果原表有 `AUTOINCREMENT`，新表定义也要加上；迁移时**保留原id值**（用 `INSERT INTO ... SELECT id...`） |
| **表有外键被其他表引用** | 删除旧表时报错 `FOREIGN KEY constraint failed` | 开头必须加 `PRAGMA foreign_keys = OFF;`，完成后记得改回 `ON` |
| **触发器或索引丢失** | 重建表不会自动迁移触发器、索引和视图 | 重建完成后，手动执行 `CREATE INDEX` 和 `CREATE TRIGGER` 语句（可以先通过 `.schema users_old` 查看并复制） |
